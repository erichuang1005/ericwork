The problem

Right design system, wrong surface.

Clinical staff run 21 inventory tasks all shift on Zebra handhelds in a healthcare facility supply area — mobile web, not native.

Canvas Mobile targets native apps. Canvas Web is Workday's default web library — optimized for desktop web, not scanners or shift-long pro use.

PM, engineering, and design aligned on Canvas Web for the rebuild. We owned product-specific component updates on top — legacy stack was sunsetting.

  • Design floor Smallest Zebra viewport — size to that minimum (~360px)
  • Input Hardware scan trigger first, touch second · gloves-on
  • Session Full shift, hundreds of lines — density beats whitespace
  • Stack React WebView — Canvas Mobile isn't available to us

Exploration

Flow polish first — not enough.

First direction: one pick at a time, scanner up top, big quantity keypad. Usability improved — but screens stayed airy. Same unfit components underneath.

With PM and engineering: stop polishing inside unfit defaults. Invest in shared building blocks the whole 21-task roadmap could reuse.

05 / 13
Strategic call

Polish flows vs. product components.

Path A

Polish each flow

Faster to demo. Same Canvas Web defaults. 21 tasks, 21 density debates. Teams fork footers and list rows.

Path B — chosen

Extend Canvas Web — don't fork

Audit 21 tasks. Re-proportion with existing tokens. Prove in batch pick → scale. Same library, mobile-web density.

Inventory · Decision
06 / 13
Discovery

21 tasks, same three gaps.

Action bars truncated at ~360px · list rows too airy · blue scanner panel squeezed forms. Full library overhaul — three examples next.

Spec from Figma

Token values and spacing from Figma specs — prompted Cursor to apply the same Canvas tokens in component code.
