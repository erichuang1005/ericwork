01

Problem

No single place to get a verified answer

Typical employee path today

Search Confluence Ask on Slack Open a purchase form Wrong guidance Compliance risk Escalate to manager ✦

Employees asked the same questions — “How do I buy X?” and “Is this allowed?” — over and over. Answers lived in wikis, Slack threads, and forms: slow to find, easy to get wrong, and they wanted the source before acting.

  • VolumeInternal support said half their week was repeat “how do I…?” questions
  • FreshnessWritten guides go out of date; training everyone again doesn’t scale
  • StakesWrong buying guidance has real compliance and financial consequences
02

Exploration

What I tried, what I ruled out, and what held up

Form-first · rejected

Failed due to guess-first routing

Structured forms worked when users already knew what they needed. For everyone else, step one was a guess — not a viable entry point.

Pure chat · rejected

Failed due to no workflow handoff

Requisition is a governed workflow — not a chatbot brief. Chat-style surfaces couldn’t keep answers in policy or hand off the next real step.

Governed chat · shipped

People ask in the thread. The reply has to cite a source. The path that spends money is set in admin, and a person still approves it.

03

Solution

Catalog, non-catalog, and the admin loop that keeps both safe

Catalog
Canvas inside the chat.

The Workday design kept catalog in conversation — a reply, a card, a button. For Sana I moved that into a catalog canvas inside agent chat so people can search, compare, and add in one place — faster, with less back-and-forth.

  1. Prev · Workday · Chat
  2. Now · Sana · Canvas
Non-catalog
A modal instead of answering in the composer.

Workday collected non-catalog details through chat — the agent asked in the thread, people typed answers in the input box. For Sana I moved that into a structured input modal: one question at a time, then a complete request. Structured capture beat free-text when the fields are required for compliance.

  1. Prev · Chat · Input
  2. Now · Sana · Modal
Admin
Upload policy. Approve the path.

Workday admins uploaded a policy document, then typed the purchase path by hand. In Sana, the same upload drafts a compliance purchase path — admins approve it and adjust the details. I kept a human in the loop on purpose: the agent proposes, the admin publishes.

  1. Prev · Workday · Manual
  2. Now · Sana · Generated

05

Outcomes

What shipped, what stuck, what I’d do next

  • 01

    Two major releases

    2024: the employee chat and the admin UI in one release. 2026: in-thread catalog, forms, and pricing.

  • 02

    Admin loop in v1

    Document upload, routing table, test sandbox, and analytics shipped with the user experience — not deferred.

  • 03

    Pattern carried forward

    The reply primitive and in-thread actions moved into Sana — canvas, structured modal, generated recipes with admin approve.

  • 04

    Repeat questions

    Internal support said half their week was repeat “how do I…?” questions. I designed against that volume — I don’t have a public reduction number to share.

“If the rules don’t match real behavior, the ‘AI’ part doesn’t matter—the experience breaks.”

I would push for a live admin preview earlier. The sandbox caught routing logic; it missed real-world edge cases until employees hit them. Next time I’d also stand up an evaluation harness so new rules get real prompts before they go live.
