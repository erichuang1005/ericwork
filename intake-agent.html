The problem

02

Exploration

What we tried, what we ruled out, and what held up

Form-first · rejected

Failed due to guess-first routing

Structured forms worked when users already knew what they needed. For everyone else, step one was a guess — not a viable entry point.

  • New hiresDidn’t know which category to pick
  • PolicyNo way to ask “is this allowed?” before committing
  • RigiditySame form structure regardless of complexity

Pure chat · rejected

Failed due to no workflow handoff

Requisition is a governed workflow — not a chatbot brief. Chat-style surfaces couldn’t keep answers in policy or hand off the next real step.

  • ContextPolicy, catalog, and approvals — not one-off Q&A
  • RoutingWeak ties to sources and deterministic routing
  • TrustJargon and tool knowledge before useful help

Hybrid entry · shipped

One entry point for repeat tasks, open search, and policy-heavy questions — with sources and a real next step.

  • ShortcutsAdmin-curated Quick Links for repeat tasks
  • SearchRole-tuned suggestions on first load
  • AssistantGrounded replies when context matters
03

The system

Admin side first — the rules that make the user experience possible

What admins configure

The assistant is only as good as its rules. Admins upload official docs (grounding answers in real policy), set routing per topic, define when the assistant must stop, then test everything in a sandbox before any employee sees it. Analytics close the loop after launch.

How the loop works

1

Admin sets the rules

Before anyone sees the assistant

  1. Upload official policy docs
  2. Route each topic to the right tool
  3. Test answers in a sandbox
2

Employees get grounded help

One entry point in the live product

  1. Ask in plain language
  2. See the answer with sources
  3. Take the next step in workflow
3

Analytics close the loop

Real usage goes back to admins

Admins refine routing and grounding from actual questions — then the cycle starts again.

Phase 1 · first ship · 2024

One page, three entry points. Three ways in from one screen: Quick Links for repeat tasks, direct search for anything, and a side assistant when the answer needs context. Replies cite the source document and offer the logical next step.

Phase 2 · requester experience

Finish the task in chat. Phase 2 extended the assistant into the workflow. Users submit catalog requests, fill off-catalog forms, and receive confirmations — all without leaving the thread.

04

Outcomes

What shipped, what we measured, and what we'd do differently

1

What shipped

Two major releases · 2024–2026

  1. Hybrid landing page (2024), then in-chat catalog and forms (2026)
  2. One consolidated entry point — policy-grounded, with explicit stop rules
  3. Admin tooling (upload, routing, sandbox, analytics) shipped with v1
  4. Adopted by Workday procurement; extended as a reusable assistant pattern
2

Reflection

What we’d do differently next time

“If the rules don’t match real behavior, the ‘AI’ part doesn’t matter—the experience breaks.”

Push for a live admin preview earlier. The sandbox helped, but seeing the full user-facing experience before launch would have caught more rule gaps before employees hit them.
