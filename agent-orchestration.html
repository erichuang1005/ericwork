Thinking · Multi-agent UX

How I think about multi-agent UX

Work in progress — thinking I’m developing alongside shipped work.

Specialized agents help only when the handoff, the write, and the permission are explicit. In the sketch, pending actions stay with a person — an agent can draft the handoff; it doesn’t clear the queue. The shipped, single-agent version of these controls is Intake Agent. Defining what that agent owns surfaced a boundary: it assumed one item and one request. A multi-item or multi-service ask doesn’t fit the model — split it, or hand it off. When a use case didn’t match at all, I redirected it to another spend or procurement agent instead of stretching Intake. That handoff is still open thinking, alongside the shipped single-agent work.

01

Where multi-agent fails

Three breaks I design for before adding another agent

Failure What breaks Design response
Handoff failures The next agent starts blank — no decision, constraint, or source. The employee gets a new thread, not a continuation. A handoff is a packet: intent, cited policy, open decision. The receiving agent shows what it inherited.
Conflicting agent actions Two agents write the same request. One adds a catalog line; another opens a form. The employee can’t tell which action is real. One owner at a time. Name the active agent. The other proposes or waits. Conflicting writes don’t both commit.
Permission bleed A specialist reaches a system of record the employee can’t touch, because the orchestrator passed a wider token. Scope travels with the task. Each agent gets the minimum for its step. More access is a request, not an inheritance.
02

Escalation

Agent to agent, or agent to human

Agent → agent when the next step is a different skill, or the request doesn’t fit this agent’s model, and the packet is complete — a policy answer handing off to catalog lookup. Stay in one thread. Show who has it.

Agent → human when the stakes are spend, a policy exception, low confidence, or a tool failure. The person gets the packet and the reason, not a blank form.

Role on the handoff. A requester, a manager or delegate, and an admin should not share one queue — submitted work, approval actions, or a broader view. Permission stays with the role. Still open thinking, same as the handoff.

Don’t send uncertainty to another agent. Uncertainty is a human handoff.
